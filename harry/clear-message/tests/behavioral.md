### R6 · 여러 요청의 상태가 바뀌는 대화

사용자가 명시한 맥락: `나는 민수입니다.`

```text
지수: 민수님, 검색 캐시 PR 오늘 안에 검토하고 결과 알려주세요. 태훈님은 배포 로그 확인 부탁드려요.
민수: 검색 캐시 검토는 제가 할게요. 오늘 가능한지는 아직 모르겠어요.
지수: 민수님께 요청한 PR 검토는 취소할게요. 태훈님 로그 확인 요청은 그대로예요. 민수님은 TTL을 5분으로 할지 의견만 부탁드려요.
태훈: 배포 로그는 제가 확인했어요. 장애는 없었어요.
지수: 감사합니다. 공유한 표는 참고해주세요. 사용자 수가 늘면 캐시도 구현해주실 수 있나요? 아직 적용 여부는 미정이에요.
민수: 5분이 괜찮아 보여요.
지수: 그 의견은 확인했어요. 캐시 구현 부탁은 사용자 수가 늘었을 때 다시 이야기할게요.
```

통과 기준: 민수의 PR 검토는 취소, TTL 의견은 회신 완료, 캐시 구현은 추후 논의로 구분한다.
민수에게 현재 남은 답변·작업 요청은 없다고 표시하며, 태훈의 완료 보고를 민수의 작업으로 옮기지 않는다.

### R7 · 독자의 역할이 주어지지 않은 대화

```text
지수: 태훈님은 PR #42를 오늘 17시까지 검토하고 승인 여부 알려주세요. 민수님은 장애가 다시 발생하면 로그를 올려주세요.
태훈: 아직 PR은 못 봤어요. 오늘 가능할 것 같아요.
지수: 일정 공유드립니다. 캐시 TTL은 5분으로 제안했지만, 사용자가 줄어서 도입 자체를 다음 주에 판단하려고 해요. 운영 적용은 미정입니다. 읽어보시고 참고만 해주세요.
```

통과 기준: 요청의 대상을 태훈·민수로 유지한다. PR 검토·회신은 있음, 로그 공유는 조건부 요청이다.
TTL 제안·다음 주 판단 계획·운영 적용 미정을 보존하며 사용자가 두 사람의 일을 모두 맡았다고 쓰지 않는다.

### W6 · 기존 약속과 현재 예상, 상대의 대응 범위

```text
민수님한테 보내려는 거예요. 지난번에 제가 금요일까지 하겠다고 했었죠. 그거 취소는 아니고 지금으로선 가능할 것 같긴 해요 근데 테스트에서 하나가 실패해요. 태훈님이 '제가 배포할게요'라고 하셨으니까 제가 배포한다는 얘기는 아니구요. PR은 지수님이 보고 계세요. 민수님은 지금 뭘 해주실 필요는 없고 진행 공유만 드리는 거예요. 검색 결과는 A 0.5 B 0.7이었는데 쿼리가 서로 달라서 B가 더 좋다고 말하기는 어렵고요. 아 캐시 만료는 5분이라고 썼는데 정정할게요 10분이에요. 구현 코드는 `cache_ttl = 600`입니다. 배포 일정은 금요일, 아니 일정 다시 확인해봐야 해요. 변경 자체는 금요일까지 가능할 것 같지만 배포 날짜는 아직 미정이에요.
```

통과 기준:

1. 민수에게 추가 행동이 필요 없다는 안내를 본문에 남긴다.
2. 기존 금요일 완료 약속이 유지된다는 사실과 현재 예상·실패한 테스트를 따로 보존한다.
3. 지수의 PR 검토와 태훈의 배포 발언을 작성자의 약속으로 바꾸지 않는다.
4. A 0.5·B 0.7과 다른 쿼리라는 비교 한계를 유지한다.
5. TTL은 명시적 정정을 반영해 10분으로 쓴다. `cache_ttl = 600`과 배포일 미정을 보존한다.

## 2026-10-13 검증 기록 · 0.1.1

현재 세션과 같은 모델을 사용하는 새 문맥의 평가 에이전트로 출력했다. 에이전트에는 해당 스킬과 원문만 제공하고 기대 결과는 제공하지 않았다.
W6은 스킬 없는 일반 편집, 기존 0.1.0, 수정 0.1.1을 각각 5회 실행했다. 모든 출력은 사람이 의미 기준으로 대조했다.

| 확인 항목 | 일반 편집 | 기존 0.1.0 | 수정 0.1.1 |
| --- | --- | --- | --- |
| W6: 상대에게 추가 행동이 필요 없다는 안내 보존 | 5/5 | 0/5 | 5/5 |

기존 출력에서 기존 약속의 유지 여부도 빠지는 경우가 있었다. 수정본 5회는 기존 약속·현재 예상·실패한 테스트를 모두 보존했다.
일반 편집도 잘 처리한 사례이므로, 이 결과는 플러그인이 일반 AI보다 항상 우수하다는 근거가 아니다.

기존 출력의 첫 문단 예:

> 민수님, 진행 상황 공유드려요. 지난번에 말씀드린 변경은 현재로서는 금요일까지 가능할 것 같아요. 다만 테스트 하나가 실패하고 있어요.

수정 출력의 첫 두 문단 예:

> 민수님, 진행 상황 공유드려요. 지금 해주실 일은 없어요.
>
> 지난번에 말씀드린 금요일까지 변경을 마치겠다는 약속은 그대로예요. 현재로서는 가능할 것 같지만, 테스트 하나가 실패하고 있어요. PR은 지수님이 보고 계세요.

R1~R7과 W1~W5는 각각 한 번의 적용 결과에서 기준을 충족했다. `read-message`의 동작 지침은 유지했다.
소규모 생성 결과 점검이며, 다른 모델·설정·실제 대화에서의 정확도나 사용자 시간을 측정한 실험은 아니다.

구조·배포 확인:

- 두 스킬의 `quick_validate.py` 검사 통과.
- 임시 Codex 설정 디렉터리에서 저장소 마켓플레이스 등록과 `clear-message@skills-harry` 0.1.1 설치 성공.
- SVG 배너 렌더링 확인, 문서 상대 경로·매니페스트 일관성·공개 대상 민감정보 점검.

## 다시 평가하기

각 사례를 다른 대화의 맥락 없이 입력한다. 스킬 호출 뒤 원문을 붙이고, 표의 의미 기준과 실제 출력을 비교한다.
지침을 바꿨다면 W6을 새 문맥에서 반복하고 W1~W5·R1~R7도 다시 확인한다. 문구를 고정하거나 정규식 일치만으로 통과를 판정하지 않는다.

구조 검사는 Codex의 기본 제작 스킬이 있는 환경에서 `harry/` 디렉터리 기준으로 실행한다.

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py clear-message/skills/read-message
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py clear-message/skills/write-message
```

실제 사용에서 아쉬운 결과는 원문을 익명화한 뒤 `입력 → 실제 출력 → 바뀌거나 빠진 의미`로 기록한다.
속도를 비교할 때는 서로 다른 메시지를 사용하고, 같은 메시지를 반복해서 읽어 생기는 학습 효과와 AI 응답 시간을 구분한다.
