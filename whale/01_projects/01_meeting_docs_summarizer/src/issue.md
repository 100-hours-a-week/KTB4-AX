# 2026-09-29 부하테스트와 AI 개발을 위한 테스트 환경 분리 필요

## 🐞 에러 내용

- 운영 서버에서 부하테스트를 진행하면 응답 지연이나 장애로 실제 사용자가 서비스를 이용하지 못할 수 있다는 우려가 제기되었다.
- AI 팀원는 운영 서비스에 영향을 주지 않고 기능을 자유롭게 개발 및 테스트할 수 있는 환경이 필요헀다.
- 두 요구를 충족하기 위해 별도 테스트 서버의 필요성을 논의헀다.

## 🔍 원인 분석

- 현재 운영 환경과 개발, 테스트 환경이 분리되어 있지 않아, 부하테스트와 AI 기능 실험이 실제 사용자 요청에 영향을 줄 수 있다.
- 운영 서버에는 서비스 안정성을 고려해야 하므로 높은 부하를 발생시키거나 AI 코드를 반복적으로 변경하는데 제약이 있다.
- 로컬 환경 만으로는 운영 서버의 자원 조건과 FE, BE, AI 간 연동을 충분히 재현하기 어렵다.

## ✅ 해결 방법

- 운영 서버와 유사한 환경의 EC2 한 대를 추가해 테스트 환경을 구성하는 방향을 결정했다.
- 기존 Docker Compose와 ECR 이미지를 활용해 FE, BE, AI 및 Nginx 구성을 재현한다.
- 테스트 DB와 환경변수를 운영과 분리해 테스트가 운영 데이터와 서비스에 영향을 주지 않도록 한다.
- 테스트 서버를 부하테스트와 AI 기능 개발, 검증에 활용한다.

## 회고

- 테스트 환경은 성능 측정 뿐 아니라 팀원이 운영 영향 없이 기능을 실험할 수 있도록 하는 데도 필요하다
- EC2를 추가하는 것만으로 격리가 완성되는 것은 아니며, DB와 외부 API 연동까지 분리해야 한다.
- 운영과 유사한 환경을 마련하되, 외부 API 비용과 호출 한도는 별도로 관리해야 한다.
